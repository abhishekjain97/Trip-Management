# 🚌 Jain Tours & Travel — Bus Seat Booking & Trip Management

A full-stack web app for a bus/tour operator to create trips, manage interactive seat charts,
take bookings (both by staff and self-service by customers via a shareable public link), track
payments, and print/export passenger manifests.

## Overview

The app has two faces:

- **Admin dashboard** — create and manage trips, view a live interactive seat chart, make manual
  bookings, block/unblock seats, override ticket prices for specific seats, track deposits and
  balances, verify payments, cancel bookings, and export a printable passenger manifest.
- **Public booking portal** — a shareable link per trip (`/trip/:shareToken`) where customers pick
  their own seats, see per-seat pricing, and submit a booking with a UPI payment screenshot.

## Features

- **Multiple bus layouts** — 2×2 sitting, 2×3 sitting, 2×2 sleeper, and 2×1 sleeper, each with its
  own seat-numbering/row/deck template.
- **Dynamic seat map** — seats are never stored in the database; they're computed on the fly from
  the trip's bus model + seat count, then overlaid with live booking/block/price data at read time.
- **Admin & public booking** — staff can book on behalf of a walk-in customer (with an editable
  advance override); customers can self-book through the public link.
- **Per-seat price overrides** — override the ticket price for any subset of seats (e.g. front-row
  or lower-deck pricing) from the trip detail page; unset seats fall back to the trip's default
  price. Already-booked seats keep the price that applied when they were booked, even if the
  override changes later.
- **Seat blocking** — mark seats as out-of-service so they can't be booked, without touching real
  reservations.
- **Payment tracking** — advance deposit + running balance per booking, payment verification
  toggle, and a UPI QR code shown to customers at checkout.
- **Booking cancellation** — frees the seat immediately for re-booking; cancelled bookings are kept
  (soft-deleted) for audit history.
- **Concurrency-safe bookings** — an in-process lock plus a database-level unique constraint
  prevent two customers from double-booking the same seat.
- **Manifest / passenger list export** — printable, paginated PDF/PNG export of the seat layout and
  passenger list, with configurable columns (mobile, price, outstanding, payment status).
- **Activity log** — a running audit trail per trip (created, updated, booked, cancelled, blocked,
  price changes, payment events).
- **WhatsApp sharing** — one-tap trip summary sharing for the public booking link.
- **Company branding settings** — company name, tagline, and logo, editable from an admin settings
  page.
- **Admin authentication** — access-key based login with server-side session tokens.

## Architecture Notes

- **No seats table.** Seat layout (codes, rows, decks) is generated by a pure function
  (`src/server/seatLayout.ts`) from `bus_model` + `total_seats`. Only what actually needs to persist
  is stored: bookings (`bookings`/`booking_seats`), blocked seats (`disabled_seats`), and price
  overrides (`seat_price_overrides`). A seat's live status/price is computed at read time by
  overlaying these onto the generated layout.
- **Dual persistence mode.** `src/server/db.ts` (`LocalDatabase`) is the single data-access layer
  for the whole app. If `SUPABASE_URL`/`SUPABASE_ANON_KEY` are set, it talks to Supabase/Postgres;
  otherwise (or if a Supabase call fails) it reads/writes a local `db.json` file — zero setup
  needed to run the app locally.
- **Batched price overrides.** `seat_price_overrides` stores one row per "apply this price to this
  batch of seats" action (an array of seat codes), rather than one row per seat, to avoid redundant
  rows when many seats share a price.

## Getting Started

### Prerequisites

- Node.js 18+
- npm

### Install

```bash
npm install
```

### Configure environment

Copy `.env.example` to `.env` and fill in what you need:

| Variable | Required | Description |
|---|---|---|
| `SUPABASE_URL` | No | Supabase project URL. Omit to run entirely on the local `db.json` file. |
| `SUPABASE_ANON_KEY` | No | Supabase anon/public API key. |
| `PORT` | No | Port to listen on (defaults to `3000`). |

If you do configure Supabase, run [`supabase_schema.sql`](./supabase_schema.sql) once in the
Supabase SQL editor to create all the required tables.

### Run in development

```bash
npm run dev
```

Serves the app (API + Vite dev server with HMR) at `http://localhost:3000`.

### Build & run in production

```bash
npm run build
npm start
```

## API Reference

All admin routes require `Authorization: Bearer <token>` from `/api/auth/login`.

**Auth**
- `POST /api/auth/login` — log in with an access key, returns a session token
- `POST /api/auth/logout`
- `POST /api/auth/change-key` — change the admin access key

**Settings**
- `GET /api/settings` — company branding info
- `POST /api/settings` — update company branding *(admin)*

**Trips** *(admin)*
- `GET /api/trips` — list all trips
- `GET /api/trips/:id` — trip details (seats, bookings, logs)
- `POST /api/trips` — create a trip
- `PUT /api/trips/:id` — update a trip

**Public booking**
- `GET /api/public/trip/:shareToken` — public trip + seat map (customer names masked)
- `POST /api/public/trip/:shareToken/book` — customer self-service booking

**Booking & seat management** *(admin)*
- `POST /api/admin/trips/:id/book` — manual booking on behalf of a customer
- `POST /api/admin/trips/:id/seats/disable` / `.../enable` — block/unblock seats
- `POST /api/admin/trips/:id/seats/price` / `.../price/reset` — set/clear per-seat price overrides
- `POST /api/admin/bookings/:bookingId/verify` — toggle payment verification
- `POST /api/admin/bookings/:bookingId/balance` — update balance paid
- `POST /api/admin/bookings/:bookingId/cancel` — cancel a booking and free its seats

## Default Admin Login

A default admin account is seeded with access key **`admin123`**. Change it immediately after
first login via *Identity → Change Access Key* (or `POST /api/auth/change-key`) before using this
